# OpenHammer v2 — Living Plan

**North star:** two humans play a complete, fair, friction-free game of 10th Edition in a browser — real rules enforcement, automatic dice and scoring, nothing to remember, nothing to look up.

## Legend (from v1's post-mortem — evidence or it didn't happen)

- `[x]` Done — **must** cite evidence: `file:line`, a test name, or a UI path. "Implemented in the engine" is not done; a feature is done when a player can reach it in the UI **and** it changes dice or state in a real game.
- `[~]` Partially done — cite what exists and name the gap.
- `[ ]` Not started.

Rules that bit v1 and are binding here:

1. Vertical slices, not layers. No building the whole engine before the client.
2. Test the wiring, not just the units — client dispatch → server reducer integration tests.
3. No orphaned code — exported symbols with zero importers get deleted or wired.
4. Engine knows no faction or edition by name; everything GW publishes lives in `content/`.

## Milestone 3 — Full game loop ✅

- [x] **Phase kinds, not phase ids**: `edition.json` phases/steps declare `kind`; reducers switch on kinds only (`packages/core/src/state/kinds.ts`) — a future edition reorders phases in data. Schema updated; consistency held by `loader.test.ts`.
- [x] **Battle-shock**: auto-runs on step entry (`battleShock.ts`, wired in `reducer.ts onEnterStep`): below-half units test 2D6 vs best Ld, failures open the Insane Bravery window before the shock lands, shocks clear at the owner's next command phase. Tests: `gameplay-m3.test.ts` (fail→shock, window use prevents shock, pass applies it, clearing).
- [x] **Reactive stratagem windows — the protocol**: queued windows processed one at a time (`windows.ts`), zero-eligible windows skipped silently (tested), pass with "don't ask again this phase" standing preference (tested), once-per-X via central usage counters, battle-shocked targets excluded with data opt-out (`allowBattleShocked` — Insane Bravery), CP/once-per-phase enforcement in `windowReducer.ts`. UI: `StratagemPrompt.tsx` modal (Use with target select / Pass / don't-ask), waiting banner for the other player. **Browser-verified 2026-07-06**: a normal move opened Fire Overwatch on the opponent's real browser; they used it through the modal; the CP was spent and the script's no-valid-weapons case logged gracefully (screenshots reviewed).
- [x] **Script registry** (the escape hatch, declared in data): `packages/content/src/scripts/wh40k-10e.ts` — core.command-reroll (advance + charge rolls), core.fire-overwatch (shared attack sequence, only unmodified 6s, interactive saves, no activation consumed), core.tank-shock, core.counter-offensive. Deferred scripts (heroic-intervention, rapid-ingress, grenade) make their stratagems silently ineligible — contract-tested in `rooms.test.ts`.
- [x] **Charge phase** (`chargeReducer.ts`): declare within 12" (no advance/fall-back/engaged/twice), server-rolled 2D6 + command-reroll window, commit validated (per-model ≤ roll, ER with EVERY target, no ER with non-targets, coherency), charge bonus = Fights First; failCharge. Overwatch/Heroic (reactive) then Tank Shock (active) windows on completion. Tests in `gameplay-m3.test.ts`.
- [x] **Fight phase** (`fightReducer.ts`): fights-first/remaining steps from step kinds, reactive player selects first, must-select enforcement (advanceStep blocked while fighters remain — tested), pile-in/consolidate ≤3" ending closer to the nearest enemy, melee through the shared attack sequence (WS, defender saves, Hazardous), Counter-Offensive + Epic Challenge windows, eligibility recheck each activation. Client: FightActions panel with selector gating (component-tested).
- [x] **Shooting refinements**: pre-resolution `shooting.targetsSelected` window so Smokescreen / Go to Ground land BEFORE dice; Pistols-only when engaged; One Shot tracked; Hazardous end-of-sequence tests; Precision allocation can bleed into an attached leader (seed-searched test in `gameplay-m3-setup.test.ts`).
- [x] **Movement refinements**: Desperate Escape (battle-shocked → every model; otherwise path-over-enemy via segment-vs-base geometry), reserves arrival (round ≥2, >9" from enemies; strategic: wholly within 6" of an edge, round-2 enemy-DZ ban), overwatch windows after moves/arrivals.
- [x] **Pre-game additions** (`setupReducer.ts`): reserves declaration with the 25% points cap, leader attach/detach (attached leaders untargetable; canLead data arrives with M4 packs — non-Character rule enforced meanwhile), Scout X moves (post-first-turn-roll, >9" from enemies). Client PreGamePrep + ScoutMoves + ReinforcementActions panels.
- [x] **Undo/takeback** (`packages/server`: replayTo/requestUndo/respondUndo): rewind = replay over the pinned initial state; free when the suffix is all your own actions AND consumed no dice; otherwise a one-click opponent approve/deny flow over the wire; a rewound roll-off re-rolls IDENTICAL dice (tested). UI: top-bar Undo button + approval modal — **browser-verified** (Alice requested, Bob's modal approved).
- [x] **Wiring evidence**: 243 tests workspace-wide (41 client incl. 25 new M3 component tests; core 152; server 27+8 undo; content 26+ scripts). The two-store integration test now plays through charge → fight with committed charges and defender-resolved melee saves across seeded runs, auto-passing windows over the real wire.
